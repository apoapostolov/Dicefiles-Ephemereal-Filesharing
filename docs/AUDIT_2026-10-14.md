# Dicefiles maintenance audit — 2026-10-14

Scope: correctness, resource use, dependencies, MCP, and useful extensions.
This source/dependency audit includes automated runtime checks. It does not
claim an exhaustive security review or measured production speedup.

## Findings implemented

| Priority | Finding | Result and code |
| --- | --- | --- |
| P1 | Remote MCP callers could use the upstream key without authenticating; remote host settings still enforced localhost only | Require a separate bearer token and explicit host allowlist beyond loopback; retain Origin checks and limit request bodies to 1 MiB. [MCP server](../scripts/mcp-server.js) |
| P1 | MCP downloads checked size after buffering the entire response and had no timeout | Bound streamed reads, reject declared oversized bodies, cancel at the cap, apply a timeout, and validate a 1–20 MiB limit. [MCP server](../scripts/mcp-server.js) |
| P1 | Cross-worker claims checked replicated memory, then wrote unconditionally | Compare-and-set against authoritative Redis JSON, preserve serialization, broadcast successful updates, and return conflict status. [Collections](../lib/broker/collections.js), [claims](../lib/request.js) |
| P1 | Claim/release routes bypassed protected-room policy | Authorize the source room before mutation. [Request access](../lib/http/request-access.js), [routes](../lib/httpserver.js) |
| P1 | Distributed-map clear called `DEL` with an uninitialized Lua variable | Delete the actual map key, preventing cleared values from returning after restart. [Lua](../lib/broker/redis/dmap-1.lua) |
| P1 | Compatible updates were missing, including production security patches | Refresh the Yarn lockfile, security overrides, SDK, Sharp, Express, compression, federation, and Socket.IO packages. [Manifest](../package.json) |
| P2 | MCP URL uploads sent an object to a REST endpoint requiring an array | Send `{url, roomid}` for every item. [MCP server](../scripts/mcp-server.js) |
| P2 | REST errors and unhealthy HTTP responses could appear successful | Set MCP `isError` for HTTP failures even when the body lacks `ok:false`. [MCP server](../scripts/mcp-server.js) |
| P2 | Writes were marked idempotent by default | Use conservative write annotations; these remain client hints, with REST scopes as the authorization boundary. [MCP server](../scripts/mcp-server.js) |
| P2 | Redirects could forward custom credentials; POST with 303 retained its body | Drop original headers across origins; remove body headers for redirected GETs; handle stream errors and IPv6 hostnames. [Network guard](../lib/net-guard.js) |

| P2 | Fedify 2.4 checks that a key's owner lists that key | Synthesize key and actor documents from approved peer pins, including rotation pins; permit no arbitrary network lookup. [Signatures](../lib/federation/signatures.js) |
| P2 | Ubuntu setup used an invalid Node expression and omitted sandbox/RAR tools | Correct escaping and install/check firejail and unrar. Multiverse/non-free repositories must provide unrar. [Setup](../scripts/setup-ubuntu.sh) |

| P3 | Webpack hashing mutated assets in a deprecated hook | Use `processAssets`, hash assets in sorted name order, and surface hashing failures. [Build config](../webpack.config.js) |

## Initial compatible dependency round

Before the round, Yarn reported 291 affected paths: 1 critical, 186 high,
90 moderate, and 14 low. These are paths, not 291 distinct vulnerabilities.
After the compatible refresh, no reported advisories are reachable from
production manifest roots. Two unique development advisories remain across
18 paths, both under Jest:

- `braces`: [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), high; the registry reports no published patch.
- `sprintf-js`: [GHSA-hp3w-g68c-fv3c](https://github.com/advisories/GHSA-hp3w-g68c-fv3c), moderate; the registry reports no published patch.

`yarn audit:dependencies` deduplicates advisories and classifies paths by their
manifest root; Yarn 1's development flags are unreliable here. It exits nonzero
for high/critical findings. `yarn audit:production` applies that threshold to
runtime roots. Neither command treats a registry failure as clean.

Keep the Express 4, Redis 4, and PDF.js 4 boundaries for this round. Their next
major upgrades need focused routing, broker, and reader acceptance. ESLint 8 and
deprecated `gm` need replacements. Jest needs a plan for its unpatched packages.
Do not force unrelated transitive majors merely to hide an advisory.

## MCP decision

The checkout already used SDK v2.1.0 and MCP 2026-07-28. It now uses server
v2.3.1 and Node adapter v2.1.1. Keep stateless HTTP: the 36 tools make independent
REST calls; room state, claims, and saved subscriptions belong in Dicefiles/Redis.
[Official serving model](https://github.com/modelcontextprotocol/typescript-sdk/blob/main/docs/serving/http.md).

Keep stdio and the SDK's stateless legacy fallback. Tests exercise actual SDK
schemas, modern HTTP with `params._meta`, older initialization, and stdio
discovery. [MCP setup](../MCP.md). The initial remote bearer-token mode grants access to one scoped upstream key.
The authorized follow-up below adds OAuth and separate caller identities.

## Follow-up implementation

All twelve rows above now have implementations in the working tree; they are
unreleased. Express 5, Redis 6, PDF.js 6, ESLint 10 flat config, and Jest 30 are
installed. GraphicsMagick was replaced by bounded Poppler/Sharp PDF previews.
Jest's obsolete YAML dependency uses the maintained js-yaml load API. The final
whole-graph Yarn audit reports zero advisories, including development paths.

The follow-up includes signed pagination, streamed/cancellable imports,
authoritative password state and guarded claim mutations, async bounded disk
probes, a durable webhook outbox, bounded audit tails and atomic config writes,
100-tile gallery pages with focus restoration, and OAuth caller isolation.
Provider work includes Gofile, fair scheduling, retry/circuit state and a disabled
Plowshare bridge with guarded egress. Storage work includes journaled copies,
checksums, renewed reservations, pause/resume/rollback and drain/rebalance plans.
Cohort and personal credentials have individual rotation, revocation and limits.

The responsive follow-up fixes a 1,350px threshold that incorrectly forced
stacked phone layout at tablet widths. Two panes now remain above 760px; saved
pane sizes use a CSS variable rather than overriding the responsive grid.

Route-contract regressions register actual paths against Express 5; optional
segments and wildcard middleware were updated. Redis SCAN accepts the Redis 6

loading task, cancels renders and disconnects observers. Continue Reading no

deployment-specific acceptance requiring operator configuration.
